# Serial Transport Layer v2 — Project Execution Plan

> Generated by workflow-architect | 2026-07-12
> Status: Completed

---

## 1. Project Vision

Stabilize the native Windows serial foundation used to diagnose PLCs and other
serial devices. One session owner controls the port lifecycle and all HANDLE
operations, every accepted operation reaches one typed terminal result, and
reconnects cannot mix old and new work. Richer scanner decoding, including
variable bit layouts and Gray code, remains a later upper-layer feature.

## 2. Architecture Overview

The UI owns one `Win32SerialSession`. Capability views let command sequences
submit writes and let RTU perform byte exchanges without exposing lifecycle or
the native handle. The session serializes open, close, read, write, DTR, and RTS;
tracks state and generation; applies operation deadlines; and owns one bounded
write queue. Localized text is created at the UI boundary from structured
transport results. The broad `SerialTransport` facade is removed directly.

```text
UI / reconnect / evidence       Command sequence       Modbus RTU
           |                          |                    |
      session commands          write capability     byte capability
           +--------------------------+--------------------+
                                      |
                              SerialSession contract
                                      |
                           Win32SerialSession (sole owner)
                           | state + generation + deadlines
                           | bounded SerialWriteQueue
                                      |
                                Win32 COM HANDLE
```

## 3. Tech Stack

| Component | Choice | Rationale |
|-----------|--------|-----------|
| Language | C++20 | Matches the native codebase and provides RAII, threads, clocks, containers, and strong value types. |
| Framework | Direct Win32 API | Required for COM configuration and I/O; keeps ownership and error semantics explicit. |
| Database | None | Transport state is transient; no persistence dependency belongs in the serial foundation. |
| Testing | CTest, fake contracts, PTY, MinGW/Wine | Preserves deterministic unit/integration coverage and the current release evidence. |
| Build Tool | CMake | Existing single source of target and test registration. |
| Deployment | Portable Windows zip via existing package scripts and GitHub Actions | Preserves package size, forbidden-runtime, import, hash, and documentation gates. |

No Boost.Asio, WIL, Qt, TCP/UDP, SQLite, plugin system, or new runtime dependency
is introduced.

## 5. Success Criteria

- [x] Exactly one `Win32SerialSession` owns the active COM HANDLE and performs all HANDLE operations.
- [x] Every accepted operation produces exactly one typed terminal result with request ID, generation, deadline outcome, byte count, and native error code when applicable.
- [x] Deterministic cancellation and disconnect tests settle within the approved `<= 1 second` target; driver-specific limitations are recorded honestly.
- [x] Reconnect increments the generation, terminates old work, suppresses stale completion, and never replays requests automatically.
- [x] Queue admission enforces 64 counted requests and 256 KiB counted bytes, including active work, with immediate rejection and no silent dropping.
- [x] Transport decisions never parse localized error text; UI localization occurs only at the presentation boundary.
- [x] Manual/timed/file send, receive polling, DTR/RTS, Modbus RTU scan, command sequence, reconnect, evidence, and current UI behavior remain available.
- [x] `SerialTransport` and all in-repo references to the broad facade are removed without a compatibility wrapper.
- [x] RTU framing and future bit-layout/encoding codecs remain above the byte/session layer; Gray code is not implemented in this project.
- [x] Linux/native CTest, MinGW/Wine CTest, PTY matrix, self-test, UI performance, package audit, size/import/forbidden-runtime checks, SHA256, and documentation checks pass.

## 6. Risk Register

| # | Risk Description | Probability | Impact | Mitigation Strategy |
|---|------------------|-------------|--------|---------------------|
| 1 | A third-party driver does not settle synchronous I/O within one second. | Medium | High | Apply explicit deadlines and native cancellation, test the target, retain an isolated overlapped-I/O seam, and document unverified hardware behavior. |
| 2 | Close/reopen races publish duplicate or stale results. | Medium | High | Use one owner, generation checks, exactly-once state transitions, and race-focused tests. |
| 3 | Direct facade removal creates a broad migration diff. | Medium | Medium | Separate contract, backend, and caller migration tasks; require focused tests and one commit per task. |
| 4 | Count/byte limits reject a previously accepted large manual payload. | Medium | Medium | Return a typed immediate rejection, keep file send chunked, and test UI feedback. |
| 5 | RTU stale bytes are mistaken for a new response. | Medium | High | Keep purge/framing/CRC and stale-RX policy in the RTU layer with adapter and PTY tests. |
| 6 | CI passes while a specific PLC/USB-serial driver fails. | Medium | Medium | Keep fake and PTY gates mandatory and maintain optional local hardware smoke guidance. |
| 7 | Future Gray-code work leaks into transport and grows the base. | Low | Medium | Add a documented and checked upper-layer codec boundary; implement no codec in transport v2. |
| 8 | Additional diagnostics expose serial payloads. | Low | High | Log structured operation metadata by default and keep payload evidence explicit/local. |
