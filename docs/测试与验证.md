# 测试与验证

状态：当前 Win32 native 测试与验证说明。工程交付以 GitHub Actions 编译出的 `svm-native-win32.exe` 和 artifact 为最终测试目标。

真实 Windows 手工验收不是本轮阻塞条件，但仍是发布前风险补充，尤其是具体 USB 转串口硬件、DTR/RTS、硬件流控和长时间现场运行。

## 基线与证据分层

当前验证采用三层证据：

| 层级 | 用途 | 是否阻塞 release |
|------|------|------------------|
| GitHub Actions package artifact | 最终交付对象，包含 zip、SHA256、package summary、CTest 日志、Phase 2 后端回归闭环说明、自检、UI 性能和 PTY local-only 说明；缺少这些证据文件会阻塞 | 是 |
| GitHub Actions UI capture artifact | 最终 UI 自动证据，包含截图、`capture-status.txt`、`ui-perf-test.log`、`window-info.txt` 和 `ui-evidence-summary.txt` | 是 |
| 本地 Windows / Linux/Wine 辅助检查 | 用于复现、诊断、真实硬件和 PTY 压力补充 | 不是默认阻塞，但发现问题必须修复 |

UI 性能和截图判断必须以最后一个用户确认可用的 release/artifact 为基线。后续任务可以收紧门禁，但不能凭空引入没有基线依据的数值阈值；如果基线文件缺失，应先补齐证据，不能把缺失解释为通过。

`upload-artifact` 相关门禁使用 `if-no-files-found: error`，但该选项只能拦住“全部路径都未匹配”的情况，不能单独证明多文件列表中的每个证据文件都存在。因此 package workflow 在上传前还会逐个断言 zip、SHA256、package summary、`native-ctest.log`、`native-self-test.log`、`native-ui-perf-test.log`、`phase-2-backend-regression.txt` 和 `serial-pty-matrix.txt` 存在且非空，并检查关键成功文本。上传成功后会在 job summary 写入 `artifact-id`、`artifact-url` 和 `artifact-digest`；`artifact-digest` 是 CI 上传证据，不能替代 zip 自带的 SHA256 sidecar。

需要存在并随 artifact 上传的 UI 证据至少包括：`*.png`、`capture-status.txt`、`self-test.log`、`ui-perf-test.log`、`window-info.txt` 和 `ui-evidence-summary.txt`。UI workflow 同样会记录上传 `artifact-digest`，该值只证明 Actions artifact 对象，不替代 `ui-perf ok`、截图细节和 `capture-status.txt` 的场景复核。

## 阻塞门禁

当前 Win32 native 发布必须通过以下门禁。

### CI 阻断与本地 RC 证据边界

| 项目 | GitHub Actions 是否执行 | 是否 CI 阻断 | 证据 |
|------|-------------------------|--------------|------|
| CMake native-only 配置和 Release 构建 | 是 | 是 | workflow log |
| Native CTest | 是 | 是 | `ctest --test-dir build-windows-native --output-on-failure -C Release` |
| native serial unit tests | 是 | 是 | `native_win32_serial_tests` |
| native loopback no-port/skip safety path | 是 | 是 | `native_win32_serial_loopback_tests` 在无端口环境下必须安全跳过或通过 |
| exe self-test | 是 | 是 | `native-self-test.log` |
| UI 性能门禁 | 是 | 是 | `native-ui-perf-test.log` |
| package 审计和 docs consistency | 是 | 是 | package summary、docs consistency 输出 |
| `serial-pty-matrix.txt` 文件存在并上传 | 是 | 是 | package artifact |
| PTY normal/reopen/timeout/cancel/stress 场景真实执行 | 否 | 否，local-only release-candidate evidence | 本地 Linux/Wine 脚本输出 |

结论：`serial-pty-matrix.txt` 是 CI 阻断的“证据说明文件”，不是 CI 已执行 PTY 压力矩阵的证明。涉及串口 I/O、异步写队列、超时/取消、重连或批量发送的 release candidate，应在本地 Linux/Wine 运行 PTY 矩阵并保留输出。

### Windows native package workflow

工作流：

```text
.github/workflows/windows-native-package.yml
```

artifact：

```text
SerialValueMatcherNative-win32-native-x64
```

阻塞检查：

- CMake native-only 配置：`SVM_BUILD_QT_APP=OFF`、`SVM_BUILD_QT_TESTS=OFF`、`SVM_BUILD_WIN32_APP=ON`。
- Release 构建：`svm-native-win32.exe`。
- CTest：`ctest --test-dir build-windows-native --output-on-failure -C Release`，输出保存为 `native-ctest.log`。
- Phase 2 后端回归闭环：`phase-2-backend-regression.txt`，说明串口写队列、Modbus executor/request/UI 状态、native 存储恢复和后续自检/UI 性能门禁的证据边界。
- exe 自检：`svm-native-win32.exe --self-test`，日志写入 `native-self-test.log`。
- UI 性能门禁：`svm-native-win32.exe --ui-perf-test`，日志写入 `native-ui-perf-test.log`。
- package 审计：zip、SHA256、exe、导入表、Unicode probe、forbidden runtime、体积门禁。
- package summary 中必须出现 `Gate status: passed`，并覆盖 `Unexpected DLL files`、`Required package files`、`Package documentation links` 和 `Package documentation file set`。
- 上传 artifact 必须包含 zip、SHA256 sidecar、package summary、`native-ctest.log`、`phase-2-backend-regression.txt`、自检日志、UI 性能日志和 `serial-pty-matrix.txt`。
- artifact 上传使用显式路径、`if-no-files-found: error` 和 14 天保留期；upload step 的 `artifact-digest` 只用于 GitHub Actions 上传对象追踪，不作为用户校验 zip 的替代。

Windows runner 不提供 POSIX PTY 和 Wine dosdevices，因此 `serial-pty-matrix.txt` 在该 workflow 中记录为 local-only 证据文件；真实 PTY 压力由本地 Linux/Wine 环境执行。

### Windows native UI capture workflow

工作流：

```text
.github/workflows/windows-native-ui-capture.yml
```

artifact：

```text
windows-native-ui-screenshots
```

阻塞检查：

- CMake native-only 配置和 Release 构建。
- CTest。
- `--self-test`。
- `--ui-perf-test`。
- `scripts/capture-windows-native-ui.ps1` screenshot capture。
- 默认窗口、小窗口、标签页切换、resize sweep、DPI smoke、分割条拖动帧。
- Phase 1 UI regression closure 状态行。
- `capture-status.txt` 中对应场景必须为 PASS。
- `self-test.log` 必须随 artifact 上传。
- `ui-perf-test.log` 必须随 artifact 上传。
- `window-info.txt` 必须记录 DPI 和窗口指标。
- `ui-evidence-summary.txt` 必须记录 `BaselinePolicy=release-artifact-derived` 和 `GateStatus=passed`。
- artifact 上传使用 `if-no-files-found: error`，缺少任一声明路径都不能算通过。

UI capture 不是只看截图是否存在，还会用图像差异验证标签切换和分割条拖动帧，防止“点中才显示控件”或“拖动无真实变化”的假通过。

## Phase 2 后端回归闭环

Phase 2 backend closure 要求同一轮 native package workflow 至少保留以下证据：

- `native-ctest.log`：Windows native Release 构建的完整 CTest 输出，必须在 package 前通过。
- `phase-2-backend-regression.txt`：说明后端闭环覆盖串口写队列、native 串口状态、Modbus core/executor/request/UI 状态、native storage 替换回滚和孤儿尾部恢复。
- `serial-pty-matrix.txt`：明确 PTY 矩阵仍是 local-only release-candidate evidence，不伪装成 Windows runner 已执行。
- `serial-pty-matrix-summary.txt`：机器可读记录 `GateStatus=documented-local-only`、`ExpectedScenarios=normal,reopen,timeout,cancel,stress` 和本地执行命令。
- `native-self-test.log` 和 `native-ui-perf-test.log`：证明同一 exe 通过应用级自检和 UI 性能门禁。

本地回归对应命令：

```bash
ctest --test-dir build-codex --output-on-failure
ctest --test-dir build-windows-native-mingw --output-on-failure
```

## exe 自检

命令：

```powershell
build-windows-native\Release\svm-native-win32.exe --self-test
```

可设置日志路径：

```powershell
$env:SVM_NATIVE_SELF_TEST_LOG = "artifacts\windows-native\native-self-test.log"
build-windows-native\Release\svm-native-win32.exe --self-test
```

覆盖重点：

- UI 文案和窗口创建基础能力。
- 串口状态、发送状态、历史、文件发送。
- 日志过滤、搜索、复制/导出相关状态。
- native 存储读写。
- Modbus 扫描结果、候选生成、规则验证、Markdown 报告。
- 分割条和布局基础行为。

## UI 性能门禁

命令：

```powershell
$env:SVM_NATIVE_SELF_TEST_LOG = "artifacts\windows-native\native-ui-perf-test.log"
build-windows-native\Release\svm-native-win32.exe --ui-perf-test
```

日志重点字段：

- `tabs`：标签切换次数。
- `tab-ms`：标签切换耗时。
- `layout-pass`：布局 pass 数。
- `apply`：布局应用数量。
- `revision`：布局 revision。
- `log-lines`：日志压力行数。
- `log-ms`：日志压力耗时。
- `log-flush`：日志 flush 次数。
- `log-rebuild`：日志重建次数。

失败时优先检查 `NativeFrameScheduler`、`NativeLayoutModel`、`NativeLayoutTransaction`、`NativePaintPolicy` 和日志 flush 路径。

当前阶段只记录基线派生策略：阈值必须来自当前稳定 release/artifact 的输出和后续可复现样本，不能为了让一次修改通过而临时放宽或自造阈值。

## PTY 串口矩阵

本地 Linux/Wine release-candidate 辅助验证：

```bash
SVM_SERIAL_LOOPBACK_SCENARIOS=normal,reopen,timeout,cancel,stress \
python3 scripts/run-windows-native-serial-pty-loopback.py
```

预期输出应包含：

- `python serial matrix gate classification: local-only release-candidate evidence`
- 每个场景的 `python serial scenario ok ...`
- 最终 `python serial matrix ok ... scenarios=normal,reopen,timeout,cancel,stress`

默认行为：

- `normal`：正常请求/响应。
- `reopen`：默认重开 3 次。
- `timeout`：无响应超时。
- `cancel`：观察请求后不返回响应，验证取消。
- `stress`：默认 5000 次交易。

常用环境变量：

- `SVM_SERIAL_LOOPBACK_EXE`：指定 `native_win32_serial_loopback_tests.exe`。
- `SVM_WINEPREFIX` 或 `WINEPREFIX`：指定 Wine prefix。
- `SVM_SERIAL_LOOPBACK_COM`：默认 `COM5`。
- `SVM_SERIAL_LOOPBACK_STRESS_ITERATIONS`：压力交易次数。
- `SVM_SERIAL_LOOPBACK_SUMMARY`：可选 summary 文件路径，成功时写入 `GateStatus=passed` 和 `Classification=local-only-release-candidate-evidence`。

## package 审计

Windows 正式路径：

```powershell
.\scripts\package-windows-native.ps1 `
  -BuildDir build-windows-native `
  -Config Release `
  -PackageDir artifacts\windows-native
```

Linux/MinGW 辅助路径：

```bash
scripts/package-windows-native-mingw.sh
```

审计字段：

- `Zip sha256`
- `Zip sha256 file matches: yes`
- `Native exe present: yes`
- `Native exe sha256`
- `Imported DLLs`
- `Forbidden Qt/SQLite/.NET runtime files`
- `Unexpected DLL files`
- `Required package files`
- `Unicode text probe`
- `Package documentation links`
- `Package documentation file set`
- `Gate status: passed`

失败即阻塞发布。常见失败见 [故障排查](故障排查.md)。

## 文档一致性

当前 docs consistency gate：

```bash
python3 scripts/check-docs-artifact-consistency.py
```

检查范围：

- `svm-native-win32.exe`、`svm-native-win32`、package artifact 和 UI capture artifact 名称。
- package workflow、UI capture workflow、self-test、ui-perf、package summary 和 forbidden runtime 术语。
- 活跃文档中的旧 Qt 包名、`svm-native.exe` 当前发布说法、Qt/.NET/windeployqt 依赖矛盾。
- Markdown 本地链接。
- legacy / 过渡文档中的旧路线引用只作为提示或忽略，不作为当前发布事实。

该门禁已接入 Windows native package workflow 和 Windows native UI capture workflow。失败时必须先修正文档、workflow 或脚本事实，不允许用跳过门禁替代修复。

## 发布前总检查

发布候选至少执行并保留：

- package workflow run id 和 `SerialValueMatcherNative-win32-native-x64` artifact。
- UI capture workflow run id 和 `windows-native-ui-screenshots` artifact。
- zip SHA256 sidecar 与本地计算结果一致。
- package summary 为 `Gate status: passed`。
- `ui-evidence-summary.txt` 为 `GateStatus=passed`。
- `serial-pty-matrix-summary.txt` 为 `GateStatus=documented-local-only`；涉及串口 I/O 改动时另附本地 PTY `GateStatus=passed` summary。
- `python3 scripts/check-docs-artifact-consistency.py` 通过。
- 如发现 release 问题，按 [Windows 发布说明](Windows发布说明.md) 的回滚和重新发布流程处理，不手工替换 zip。

## 未来增强

以下能力未作为当前阻塞门禁：

- 代码签名。
- 发布 attestation。
- WPR/WPA 性能采样。
- 8 小时或 24 小时长跑压力。
- 多型号真实 USB 转串口硬件矩阵。

这些项目可以作为后续发布硬化，不应在当前文档中写成已经实现。
