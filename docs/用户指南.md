# 用户指南

状态：当前 Win32 native 用户指南。本文只描述 `svm-native-win32.exe` 当前可用行为。

适用对象：中文 Windows 用户、开发测试工程师、现场调试人员。

## 获取和启动

当前主发布物是 Win32 native 便携包。正式验证对象来自 GitHub Actions 或 Release 中的 Windows native artifact：

```text
SerialValueMatcherNative-win32-native-x64.zip
```

解压后运行主程序：

```text
svm-native-win32.exe
```

使用口径：

- 不需要安装器。
- 不要求管理员权限。
- 不依赖 Qt 运行库、SQLite 插件或 .NET/C# 运行库。
- zip 的 SHA256、包体内容和构建证据以同批 artifact 中的 `.sha256.txt`、`.package-summary.txt` 和验证日志为准。
- Qt 路线源码仅作为历史基线和部分测试参考，不是当前轻量发布包。

## 界面总览

![串口值匹配器 Windows Native 主界面](images/native-ui-overview.png)

主界面分为四块：

- 顶部菜单：文件、串口、工具、分析、视图、帮助。
- 左上串口选择区：端口、波特率、数据位、校验、停止位、流控、DTR、RTS、自动重连、连接和断开。
- 中部功能工作区：单发、多发、文件、扫描、设置标签页。
- 下方通信日志：收发记录、显示格式、编码、过滤、搜索、复制、导出、暂停滚动。

功能工作区和通信日志之间的分割条支持上下拖动，用来调整标签页区域和日志区域高度。
主窗口尺寸、功能工作区高度和常用界面偏好会自动保存，下次启动恢复。

## 串口连接

1. 插入串口设备或 USB 转串口适配器。
2. 点击“刷新”，确认设备出现在“串口”下拉框。
3. 选择端口和参数：波特率、数据位、校验、停止位、流控。
4. 按设备要求设置 DTR、RTS。使用 RTS/CTS 硬件流控时，RTS 可能由系统自动管理。
5. 需要断线恢复时勾选“自动重连”。
6. 点击“连接”。状态栏和通信日志会显示连接结果。

注意事项：

- 程序只访问用户选择的本地串口和文件，不联网、不上传、不做遥测。
- 串口被其他程序占用时会打开失败，需要先关闭占用程序。
- 热插拔、DTR/RTS、硬件流控表现取决于具体适配器和驱动。
- “保存配置”会保存默认串口参数，方便下次启动恢复。

## 通信日志

通信日志用于观察 TX/RX、系统状态和导出证据。

常用操作：

- “显示”：切换十六进制、十进制、二进制、文本、HEX+文本。
- “编码”：设置日志文本解码编码，例如 UTF-8、GBK、ANSI、ASCII。
- “过滤”：只显示包含关键词的可见日志行。
- “搜索”和“查找”：定位可见日志中的关键词。
- “复制”：复制当前可见通信日志。
- “导出”：导出当前可见通信日志为文本文件。
- “暂停滚动”：停止自动跟随最新日志，便于回看历史；数据仍继续接收并写入 native 存储。
- “恢复滚动”或菜单中的“跟随最新日志”：回到底部继续跟随最新记录。
- “清空”：清空接收区显示，不删除 native 存储中的原始记录。

证据边界：

- 可见日志缓存控制 UI 中保留和渲染的日志体量。
- 完整原始 TX/RX 记录会写入 native 存储，但可见日志导出只导出当前可见结果。
- 高速长时间运行时，建议在“设置”中选择合适的日志缓存和原始记录保留规模，避免 UI 占用持续增长。

## 单发

“单发”适合临时命令、单次查询和小批量调试。

1. 打开“单发”标签页。
2. 选择“模式”：文本、HEX 字节流、十进制字节流、二进制字节流。
3. 文本模式下选择“编码”和“行尾”。
4. 输入发送内容。
5. 点击“发送”。

输入格式：

- 文本：按所选发送编码转换为字节。
- HEX 字节流：示例 `01 03 00 00`。
- 十进制字节流：示例 `1 2 255`，每个字节范围为 0 到 255。
- 二进制字节流：示例 `00000001 00000010`，每 8 位为一个字节。

勾选“定时”前先设置“周期(ms)”。开启后会按当前内容和模式周期发送，关闭后停止。

发送历史会记录常用内容、模式、行尾和发送编码，便于回填复用。

## 多发

“多发”适合固定测试流程和常用指令组。

- 页面提供 10 组快捷发送槽位。
- 每组输入框右侧的“发送”按钮只发送该组内容。
- 建议按测试步骤顺序排列常用命令，减少现场重复输入。
- 快捷发送内容为空时不会发送，并会给出状态提示。

## 文件发送

“文件”适合发送已有二进制或文本文件。

1. 打开“文件”标签页。
2. 点击“选择”，选择要发送的文件。
3. 设置“分块延迟”。延迟越大越稳，但整体发送越慢。
4. 点击“发送文件”。
5. 观察“发送进度”。
6. 需要中止时点击“停止”。

建议先用小文件验证设备响应，再发送大文件。文件发送过程中再次发送文件会被拦截，需要先停止或等待完成。

## Modbus 扫描和数值匹配

“扫描”标签页用于 Modbus RTU 基础扫描、候选生成、规则验证和报告导出。

基本流程：

1. 先连接串口。
2. 打开“扫描”标签页。
3. 设置扫描参数：从站、功能、起始地址、结束地址。
4. 功能码支持 FC03 保持寄存器和 FC04 输入寄存器。
5. 点击“Modbus 扫描”，观察进度、成功块、失败块和观测数量。
6. 需要中止时点击“停止扫描”。当前请求结束后停止生效。
7. 在“已知值匹配”中填写变量名、当前值、单位、误差。
8. 点击“分析生成”，从最近扫描结果中生成候选寄存器。
9. 点击“规则验证”，保存并验证协议字段规则。
10. 点击“导出报告”，导出 Markdown 验证报告。

边界说明：

- 未连接串口时不能执行 Modbus 扫描。
- 没有扫描结果或扫描没有寄存器观测时，不能生成候选。
- 候选结果只说明寄存器观测值和已知值存在匹配关系，仍需要结合现场业务语义确认。
- 大范围扫描应关注设备超时、失败块数量和取消响应。

## 设置

“设置”标签页用于控制日志和本地记录规模。

- “日志缓存”：限制 UI 可见日志占用。大缓存便于回看，但会增加 UI 内存占用。
- “原始记录”：限制本地 TX/RX 持久化体量。不限制会让长时间追溯更方便，但占用会增长。
- 高负载调试建议从 100M 或 500M 级别开始，根据实际设备吞吐和回看需求调整。

界面偏好、窗口尺寸、日志色系、日志时间显示等会在退出或调整后保存。当前版本提供默认、柔和、高对比日志色系。

## 导出和交付证据

常用交付证据：

- 通信日志：在通信日志区点击“导出”，保存当前可见日志。
- 规则验证报告：在“扫描”标签页完成规则验证后点击“导出报告”，保存 Markdown 报告。
- 当前发布包证据：保留同批 artifact 中的 zip、SHA256、package summary、自测日志、UI 性能日志和串口 PTY matrix。

用于问题定位时，建议同时提供：

- `svm-native-win32.exe` 所在 zip 名称和 SHA256。
- 串口参数、设备型号、USB 转串口芯片或驱动信息。
- 复现步骤、日志导出文件、截图或录屏。
- Modbus 从站、功能码、地址范围、超时/失败表现。

- CI、自测、UI 截图、PTY 串口仿真、包体审计：见 [测试与验证](测试与验证.md)。
- artifact 内容、SHA256 和发布证据：见 [发布产物](发布产物.md)。

## 当前边界

当前版本已覆盖轻量串口调试、日志证据、基础发送、文件发送、FC03/FC04 Modbus 扫描、候选分析、规则验证和报告导出。

仍建议在真实设备上重点验证：

- 具体 USB 转串口芯片的枚举、热插拔、断线恢复。
- DTR/RTS 和硬件流控的设备侧效果。
- 高速连续收发和长时间运行。
- 大范围 Modbus 扫描的超时、取消和错误恢复。
- 候选分析和规则验证结果是否符合现场业务语义。
