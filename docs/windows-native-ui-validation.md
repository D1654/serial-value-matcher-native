# Windows Native UI 验收清单

本文用于验证 `svm-native-win32.exe`。该目标是第一阶段 Win32 原生 UI shell，默认不替代 Qt baseline。

## 自动验证

在 Windows 构建目录运行：

```powershell
.\svm-native-win32.exe --self-test
```

期望：

- 进程退出码为 `0`；
- 不弹出窗口；
- 不加载 `Qt6*.dll`、`qsqlite.dll` 或 .NET/C# 运行库；
- 能创建临时 native storage，并写入 raw I/O、串口 Profile、发送历史记录和界面偏好；
- 能完成中文 UTF-8/UTF-16 往返转换检查；
- 能通过 Win32 native 关键工具栏和紧凑宽度的最小尺寸布局自检。

## 手工验证

| 场景 | 步骤 | 期望结果 |
|------|------|----------|
| 中文显示 | 启动程序 | 窗口标题、菜单、按钮、状态栏均显示正常中文，不出现乱码 |
| 启动 | 双击 `svm-native-win32.exe` | 显示中文窗口“串口值匹配器 Win32 Native”，窗口上方有“文件 / 串口 / 工具 / 分析 / 视图 / 帮助”菜单 |
| 界面结构 | 观察主窗口 | 顶部为“连接与串口参数”，左侧为“发送控制”和“扫描与分析工作流”，右侧为“通信日志”，底部为状态栏 |
| 小屏缩放 | 将窗口缩小到接近最小尺寸，再逐步放大 | 控件自动进入紧凑排版，按钮、下拉框、日志工具栏和状态栏不互相遮挡；放大后恢复更宽松的两栏布局 |
| 发送控制排版 | 观察“发送控制”首行 | 显示固定标签“模式 / 编码 / 行尾 / 历史”，下方控件与标签一一对应 |
| 工作流提示 | 观察“扫描与分析工作流”区域 | 正常尺寸显示连接设备、扫描寄存器、生成候选、验证规则、导出报告的中文流程提示；紧凑尺寸可隐藏该提示以优先保留实际操作控件 |
| 刷新串口 | 插入 USB 转串口并点击“刷新” | 下拉框出现 `COMx`，能显示系统提供的设备名称或描述 |
| 串口参数 | 修改波特率、数据位、校验、停止位、流控、DTR/RTS | 点击“连接”时使用当前参数；参数无效时显示中文错误 |
| Profile | 选择串口参数并点击“保存配置” | 下次启动恢复默认配置 |
| 界面偏好 | 切换色系、日志格式、日志编码、日志时间、发送模式和窗口尺寸后关闭重开 | 下次启动恢复这些界面偏好 |
| 文本发送 | 选择“文本”，选择发送编码，输入中文或 ASCII，选择行尾后点击“发送” | 日志显示 TX 字节，设备收到所选编码字节流和所选行尾 |
| HEX 发送 | 选择“HEX 字节流”，输入 `01 03 00 00 00 01` | 非法字符或奇数半字节给出中文错误，合法输入发送成功 |
| 十进制发送 | 选择“十进制字节流”，输入 `1 2 255` | 作为多字节流发送 `01 02 FF`，超出 0-255 时显示中文错误 |
| 二进制发送 | 选择“二进制字节流”，输入 `00000001 00000010` | 作为多字节流发送 `01 02`，不足 8 位或非法字符时显示中文错误 |
| 发送历史 | 成功发送后展开“发送历史” | 可恢复最近发送内容、发送模式、行尾和发送编码 |
| 接收 | 外部设备或回环线返回数据 | 日志显示 RX 数据；可切换 HEX、十进制、二进制、文本、HEX+文本显示格式 |
| 日志编码 | 在通信日志顶部切换日志编码 | 文本与 HEX+文本显示按日志编码解码，不影响文本发送编码 |
| 日志时间 | 在“视图”菜单切换“显示日志时间” | 新增日志行按设置显示或隐藏时间戳 |
| 日志色系 | 在“视图”菜单切换默认/柔和/高对比色系 | TX、RX、Modbus、系统和错误日志保持可区分颜色 |
| 日志工具栏排版 | 观察“通信日志”顶部 | 第一行是“显示 / 编码 / 复制 / 导出”，第二行是“过滤 / 搜索 / 查找”；“查找”按钮紧邻搜索框 |
| 日志过滤 | 在通信日志顶部“过滤”输入 `TX` 或 `RX` | 短延迟后日志区只显示匹配行，原始 native 存储不被删除 |
| 日志搜索 | 在“搜索”输入关键字并点击“查找” | 光标定位到当前可见日志中的匹配文本，再次点击继续查找 |
| 日志复制 | 点击“复制”或菜单“工具 / 复制可见日志” | 剪贴板获得当前可见通信日志文本 |
| 日志导出 | 点击“导出”或菜单“工具 / 导出可见日志” | 弹出保存对话框，导出 UTF-8 文本日志 |
| 暂停滚动 | 点击“暂停滚动”后持续接收 | 状态栏显示隐藏日志数量；数据仍写入 native 存储 |
| 流式日志回看 | 持续轮询或接收流式数据时，将通信日志向上滚动到历史位置 | 新日志继续追加，但视图保持在当前历史位置，不自动跳回最新；滚动到底部或菜单“工具 / 跟随最新日志”后恢复跟随 |
| 自动重连 | 勾选“自动重连”后拔插设备 | 设备恢复后按上次参数尝试重连，并显示中文状态 |
| Modbus 扫描 | 连接串口，在“扫描参数”下设置从站/功能码/起止地址，点击“Modbus 扫描” | 执行 FC03/FC04 基础扫描，TX/RX 写入日志和 native 存储 |
| 分析入口 | 在“目标与候选”下输入字段、目标值、单位和容差，点击“分析生成” | 从最近一次扫描生成候选，候选下拉框显示候选结果 |
| 规则验证 | 选择候选后点击“规则验证” | 保存候选规则并基于最近扫描生成规则验证结果 |
| 报告导出 | 完成规则验证后点击“导出报告” | 弹出保存对话框并导出 UTF-8 Markdown 报告 |
| 长期运行 | 连续接收大量数据或单条超长数据 | 通信日志只保留最近有界工作集，单条超长日志可截断显示；完整原始数据仍写入 native 存储，窗口不持续涨内存 |
| 断开 | 点击“断开”或关闭窗口 | 串口句柄释放，其他串口工具可重新打开端口 |

## 当前边界

- 该 shell 覆盖核心串口调试工作流：刷新、连接、断开、完整串口参数、文本/HEX/十进制/二进制字节流发送、发送编码、行尾、发送历史、Profile、界面偏好持久化、彩色通信日志、日志显示格式、日志编码、日志时间开关、日志过滤/搜索/复制/导出、raw I/O 存储、暂停滚动、跟随最新日志和基础自动重连。
- 通信日志 UI 已采用有界工作集；高负荷长期运行时优先保证 UI 内存可控。用户回看历史日志时不会被流式追加强制拉回底部，完整原始 TX/RX 仍以 native storage 为准。
- 基础 FC03/FC04 Modbus 扫描入口已接入 Win32 串口后端和 native 存储，用于真机验证轻量路线。
- 候选生成、规则验证和报告导出已具备轻量 native 工作流；稳定性分析、规则编辑表格和更丰富的证据浏览仍未达到 Qt baseline 的完整交互深度。
