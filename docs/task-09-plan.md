# Task 09：人工确认候选并保存为协议字段规则

## 1. 目标

在 Task 08 已能查看稳定候选、证据链详情后，新增“人工确认”闭环：用户选择一个稳定候选，输入字段名称，把它保存为可复用的协议字段规则。

Task 09 的关键原则是：候选即使高置信，也不能自动变成规则；必须经过人工确认，才能进入协议规则资产。

## 2. 边界原则

- 不自动确认候选；
- 不修改既有扫描、候选生成、稳定性分析逻辑；
- 不重构主窗口，仅在分析工作区详情区域增加确认入口；
- 保存规则时保留来源稳定候选和证据摘要，便于追溯；
- 规则导出、规则编辑器、多规则应用验证放到后续任务。

## 3. T09A：协议字段规则持久化与 UI 确认入口（已完成）

新增：

- `src/storage/protocol_rule_records.h`
- SQLite 表 `protocol_field_rules`
- `SessionStore::saveProtocolFieldRule()`
- `SessionStore::protocolFieldRule()`
- `SessionStore::recentProtocolFieldRules()`
- `tests/protocol_rule_persistence_tests.cpp`

规则字段包括：

- rule id；
- 字段名称；
- 来源 stability run id；
- 来源 stable candidate id；
- 候选类型；
- 字序/字节序；
- slave/function；
- 起始地址/寄存器数量；
- 倍率/偏移；
- 单位；
- 置信等级；
- 稳定性评分；
- 证据摘要；
- 创建时间。

UI：

- 稳定候选详情区域新增“确认为协议字段规则”按钮；
- 用户选择稳定候选后，点击按钮输入字段名称；
- 保存成功后显示中文提示；
- 未选择候选、字段名为空、保存失败时均显示中文提示。

验收：

- 协议字段规则保存、读取、更新、最近规则列表有测试覆盖；
- `svm-native` app 目标编译通过；
- 单线程/双线程低并发全量 `ctest` 通过；
- UI 改动仍局限于分析工作区弹窗，不重构主窗口。

## 4. T09B：协议字段规则列表/查看入口（已完成）

在“分析工作区”底部新增“已确认协议字段规则”列表：

- 如果暂无规则，显示中文空状态说明；
- 如果已有规则，显示最近确认的规则；
- 表格字段包括字段名、类型、地址、寄存器数量、字序/字节序、置信等级、稳定分、来源候选和创建时间；
- 确认新规则成功后提示用户重新打开分析工作区即可在规则列表查看。

验收：

- 复用 `recentProtocolFieldRules()` 持久化测试覆盖；
- `svm-native` app 目标编译通过；
- 全量 `ctest` 通过；
- UI 改动仍局限于分析工作区弹窗，不重构主窗口。

## 5. T09C：规则编辑与删除（已完成）

新增协议字段规则的维护入口：

- `SessionStore::deleteProtocolFieldRule()` 支持按 rule id 删除规则；
- 持久化测试覆盖规则删除和空 rule id 中文错误；
- 已确认规则列表下方新增“编辑选中规则”和“删除选中规则”按钮；
- 编辑入口支持修改字段名称和单位，字段名称为空时中文提示；
- 删除入口带确认弹窗，并说明删除规则不会影响原始扫描、候选和稳定性分析记录；
- 删除后从当前规则表移除该行，编辑后即时更新表格中的字段名。

验收：

- `protocol_rule_persistence_tests` 定向通过；
- `svm-native` app 目标编译通过；
- 全量 `ctest` 通过；
- UI 改动仍局限于分析工作区弹窗，不重构主窗口。
