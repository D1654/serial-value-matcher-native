# 开发者指南

状态：当前 Win32 native 开发指南。本文面向继续维护 `svm-native-win32.exe` 的开发者和测试工程师。

## 当前开发口径

- 当前用户发布路线是 Win32 native。
- 主可执行目标是 `svm-native-win32`，发布文件名是 `svm-native-win32.exe`。
- 构建系统是 CMake，语言标准是 C++20。
- 用户可见能力优先落在 `src/core/`、`src/native_storage/` 和 `src/win32/`。

## 目录边界

- `src/core/`：协议、Modbus、候选分析和报告的框架无关核心逻辑，目标库是 `svm_slim_core`。
- `src/transport/`：唯一串口传输契约、RTU adapter 和异步写队列。
- `src/native_storage/`：native 文件存储，不依赖 SQLite 插件，目标库是 `svm_native_storage`。
- `src/win32/`：Win32 原生 UI、串口、布局、日志、发送、Modbus worker、偏好和状态模块。
- `tests/`：native 单元测试、Win32 串口测试、UI 布局/调度/绘制策略测试。
- `scripts/`：本地 MinGW 构建、打包、Wine UI capture、PTY 串口仿真、包体审计脚本。
- `.github/workflows/`：Windows native package 和 Windows native UI capture 工作流。
- `docs/`：Win32 native 架构、测试、发布和验收文档。

## Windows native 构建

正式 CI 使用 Windows runner、Visual Studio 2022、x64、Release 配置：

```powershell
cmake -S . -B build-windows-native `
  -G "Visual Studio 17 2022" `
  -A x64 `
  -DSVM_BUILD_WIN32_APP=ON

cmake --build build-windows-native --config Release --parallel 1
```

运行 CTest：

```powershell
ctest --test-dir build-windows-native --output-on-failure -C Release
```

运行 exe 自检和 UI 性能门禁：

```powershell
build-windows-native\Release\svm-native-win32.exe --self-test
build-windows-native\Release\svm-native-win32.exe --ui-perf-test
```

打包：

```powershell
.\scripts\package-windows-native.ps1 `
  -BuildDir build-windows-native `
  -Config Release
```

## Linux/MinGW 本地构建

Linux 开发环境可用 MinGW 交叉构建 Windows native exe：

```bash
scripts/build-windows-native-mingw.sh
```

默认输出：

```text
build-windows-native-mingw/svm-native-win32.exe
```

本地打包和静态审计：

```bash
scripts/package-windows-native-mingw.sh
```

本地打包脚本会调用 `scripts/inspect-windows-package.py` 检查 zip、SHA256、exe、导入表、Unicode probe、forbidden runtime 和体积门禁。Wine/Xvfb 可用时还会执行 `--self-test` 和 `--ui-perf-test`。


本地 UI capture 成功后应检查：

- `capture-status.txt` 不含 `FAIL`。
- `ui-perf-test.log` 包含 `ui-perf ok` 和 tabs、layout、log flush 指标。
- `ui-evidence-summary.txt` 包含 `GateStatus=passed`。

本地 PTY 成功后应检查：

- 命令行包含 `python serial matrix summary gate-status=passed`。
- `serial-pty-matrix-summary.txt` 包含 `GateStatus=passed`、`Classification=local-only-release-candidate-evidence` 和 `Transport=serial-adapter-contract`。

关键 exe 参数：

- `--self-test`：覆盖核心状态、日志、发送、文件发送、Modbus/分析/报告、存储和基础 UI 状态。
- `--ui-perf-test`：覆盖标签切换、布局应用、日志 flush、日志重建和拖动帧性能门禁。

## 开发原则

功能改动应先判断归属：

- 协议、数值、报告格式：优先放到 `src/core/`。
- 持久化格式和记录读写：放到 `src/native_storage/`。
- 串口契约、RTU adapter 和队列：放到 `src/transport/`；Windows handle、DTR/RTS 和端口枚举：放到 `src/win32/win32_serial_*`。
- UI 状态、布局、日志、发送、扫描和交互：放到 `src/win32/native_*` 或对应 `main_window_*.cpp`。
- 用户可见中文文案：集中到 `src/win32/ui_text.cpp`。

### 串口与 codec 依赖方向

- `serial_session.h`、`serial_types.h` 和 `serial_write_queue.h` 是 neutral transport，不能依赖 Win32、UI、matcher、codec 或存储类型。
- `Win32SerialSession` 是唯一串口设备 `HANDLE` 和串口会话 owner；调用方只能借用 `SerialSession`、`SerialByteStream` 和 `SerialWriteScheduler`。
- `SerialRtuTransport` 位于原始字节之上，RTU framing、CRC、stale-RX、retry 和协议错误不得下沉到 neutral transport。
- scanner/matcher codec 只能消费协议层输出。transport 不知道数据位位置、Gray code、signedness、缩放或设备语义。

未来扩展可变位布局或设备编码时，按以下清单执行：

1. 在 `src/core/` 设计独立的字段布局和 codec 类型，不访问 `HANDLE` 或 HWND。
2. 只消费已经读取并完成协议校验的字节/寄存器结果；除非 byte semantics 真正改变，否则不修改串口契约。
3. 为 binary、Gray、signedness、scaling、跨寄存器位段和错误配置分别编写确定性 codec 测试。
4. UI 控件和持久化格式作为独立变更评审，不把设备规则塞进 transport。
5. 区分已有固定 `Gray16` 分析候选、发送用 `NativeSendCodec` 和未来通用 scanner/matcher codec，不能混用名称或职责。

transport v2 未实现 Gray-code decoding 或通用可变位布局 codec，本轮也没有新增对应 UI 控件和持久化格式。

热路径改动要求：

- 不在 `WM_SIZE`、分割条拖动、标签切换、日志 flush 中做无界重建。
- 布局计算走 `NativeLayoutModel`，控件移动走 `NativeLayoutTransaction`。
- 高频 UI 更新走 `NativeFrameScheduler` 合并，不直接散落 `InvalidateRect`/`MoveWindow`。
- 绘制刷新策略走 `NativePaintPolicy`，避免大面积 erase background 导致闪烁。
- 日志追加优先批量 flush，保留暂停滚动、可见缓存和 native 原始记录边界。

## 提交流程

1. 明确改动归属，避免把框架依赖重新引入 Win32 native 发布包。
2. 为新增状态或算法补 native 单元测试。
3. 涉及 UI 热路径时补布局、调度、绘制或 UI capture 证据。
4. 涉及串口时补 `native_win32_serial_tests` 或 PTY loopback 场景。
5. 涉及发布物时补包体审计、hash、forbidden runtime 和 artifact 说明。
6. 提交前运行目标测试和 `git diff --check`。

## CI 和 artifact

正式发布验证入口：

- `.github/workflows/windows-native-package.yml`：构建、CTest、自检、UI perf、包体审计、上传 native artifact。
- `.github/workflows/windows-native-ui-capture.yml`：默认窗口、小窗口、标签切换、分割条拖动、UI perf 和截图证据。

当前主 artifact 名称：

```text
SerialValueMatcherNative-win32-native-x64
```

package artifact 应包含 zip、SHA256、package summary、`native-ctest.log`、`native-self-test.log`、`native-ui-perf-test.log`、`phase-2-backend-regression.txt`、`serial-pty-matrix.txt` 和 `serial-pty-matrix-summary.txt`。

UI artifact 应包含 screenshot、`capture-status.txt`、`self-test.log`、`ui-perf-test.log`、`window-info.txt` 和 `ui-evidence-summary.txt`。

发布前不要只看 workflow 绿灯；必须下载 artifact，核对 package summary、UI evidence summary、SHA256 sidecar 和 docs consistency 输出。回滚或重新发布见 [Windows 发布说明](Windows发布说明.md)。
